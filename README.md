# dnd5r-skill

> **Claude Code skill**：让 Claude 成为你的中文 DnD 5e 2024（5r）助手——查证规则、车卡、查法术、**当 DM 带你跑模组**、**按需定制改写模组（单人 / 双人 / 克苏鲁风味 / 治愈向 / 主线设定调整 …）**，全部基于"DND 五版不全书"中文资料库，**绝不靠训练记忆瞎编**。

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

## 这是什么

一个针对 [Claude Code](https://docs.claude.com/en/docs/claude-code) 的 [skill](https://docs.claude.com/en/docs/claude-code/skills)。装上之后，你可以这样和 Claude 对话：

- "帮我用魔契师车一张 5 级卡" → 自动从 PHB24 查职业、子职、专长，给你一张可点可投骰的 HTML 电子卡
- "5r 法师 1 环法术推荐哪个" → 直接读《玩家手册2024/法术速查/法师法术速查》给推荐
- "火球术升 4 环加多少伤害" → 翻 `法术详述/3环.htm#Fireball` 引用原文回答
- "战士的灵能武士子职业怎么样" → 读 `灵能武士.htm` 给评价
- "成年红龙的喷吐多少伤害" → 翻怪物图鉴 2025
- **"你来当 DM 带我跑风骸岛之龙"** → 进 DM 模式，按章节读叙事、判定检定、管理战斗、记 session 日志
- **"做个双人克苏鲁版的风骸岛"** → 自动改写模组为定制副本（怪物缩放、NPC 风味调整、剧情骨架不动），跑团时直接用

> 📦 **DM 跑团**：本仓库附带 [示范战役骨架](campaigns/风骸岛之龙-demo/) 展示 Step 1 文件系统的目录结构 + schema，但**不附带任何模组内容**（版权原因）。要跑团你需要自己准备模组（PDF / 文本放进 `docs/modules/<模组名>/`，第一次开桌时让 Claude 抽取组织，详见下文「DM 跑团」小节）。查证类功能（规则 / 法术 / 怪物 / 车卡）**开箱即用**，无需任何额外准备。

**关键约束：所有规则数值都先 grep 资料库再回答**——SKILL.md 第一条规则就是「绝不能用训练记忆答」，因为 5e 2024（5r）和训练数据里的 5e 2014 已经有大量差异。**模组剧情同理**：所有 NPC / 遭遇 / 数值都从你放在 `docs/modules/<模组名>/` 的资料里查，不凭训练记忆补编。

## 已实现的能力

### 1. 资料查证

`docs/extracted/` 下是完整的"DND 五版不全书"，已转 UTF-8 + 解开锚点，包含：

- 玩家手册 2024（PHB24）— 12 职业 + 子职、种族、背景、专长、装备、所有环阶法术详述
- 城主指南 2024（DMG24）
- 怪物图鉴 2025（MM25）
- 法术速查（按职业分表）、怪物速查、种族速查
- 旧版 PHB14 / DMG14 / MM14、塔莎、珊娜萨、贤者谏言、万象无常等扩展
- 多个设定集（艾伯伦、龙枪、星界、费资本、范·里希腾...）

### 2. HTML 电子角色卡

`templates/character-sheet.html` 是一个**完全自包含**的单文件交互卡：

- 单文件、零外链：CSS/JS/字体/数据全部内联，离线可用
- 复制到任何位置都能用——发微信、放手机/iPad/电脑、浏览器打开即是
- 内置投骰对话框（属性、技能、攻击、伤害、法术）支持优势/劣势
- HP / 法术位 / 职业资源（pip 池）/ 死豁 / 状态 / 抗性 / 装备负重 / 历史骰史
- 短休 / 长休一键、自动恢复对应资源
- 主题切换（深色/浅色）
- LocalStorage 自动存档（同设备同浏览器记得状态）
- **兼职支持**：混合 HD 显示（如 `d8×3 + d6×2`），短休时按骰型分组依次询问消耗
- **特殊投骰面板**：例如混沌施法术士的 d100 法力狂潮表，点按钮自动投骰、查表、续投子骰、写入历史

### 3. 通过 build-sheet.py 出卡

```bash
# 输入：JSON（schema 见 SKILL.md）
# 输出：自包含 HTML
python templates/build-sheet.py - output.html <<'EOF'
{ "meta": {...}, "abilities": {...}, ... }
EOF
```

或者 Windows PowerShell 走文件方式（heredoc 不可靠）：

```powershell
python templates/build-sheet.py character.json output.html
```

### 4. DM 跑团（带模组）

SKILL.md **工作流 G** 让 Claude 切换为 DM 模式带你跑一本团。AI 跑团多为单人 / 双人，所以这个工作流专为小团设计。

> 📦 **附带内容**：本仓库附带 [示范战役骨架](campaigns/风骸岛之龙-demo/) 演示 Step 1 的目录结构和 schema，但**不附带任何模组内容**（版权原因）。要跑团需要把模组 PDF / 文本放进 `docs/modules/<模组名>/`，让 Claude 第一次开桌前抽取并组织。demo 战役里的 NPC 数据块引用都标注为"需自备模组数据"。

**Step 1（2026-05）引入文件持久化战役系统**——所有跑团状态（战斗 / 玩家 / NPC / 世界 / DM 风格 / 房规）落到 `campaigns/<战役名>/` 目录，不再仅靠对话上下文。完整设计见 [STEP1_DESIGN.md](STEP1_DESIGN.md)。

**怎么用**：

1. 模组资料放 `docs/modules/<模组中文名>/`（本仓库**不附带**任何模组，需自备），结构化文件由 Claude 抽取：
   - `README.md` — 模组速览 + 剧情骨架 + 🔒 DM 秘密
   - `00_DM跑团指南.md` ~ `0N_第N章_*.md` — 按 PDF 章节切分
   - `NPC速查.md` / `地点速查.md` / `遭遇与战斗.md` / `怪物与法宝速查.md` — 跑团索引
2. 跑团时说「开桌带我跑 X 模组」，Claude 走 **G1 七步初始化**：
   1. 确定模组 → 2. 选 DM 风格 → 3. 定房规 → 4. 阵容 → 5. 车卡 → 6. 建战役目录 → 7. 开场叙事
3. **DM 风格预设**（[profiles/dm-styles/](profiles/dm-styles/README.md)）—— 6 个预设可选：标准 / 严格RAW / 宽松爽团 / 粉红恋爱向 / 黑暗残酷 / 治愈日常；战役引用 + override 微调。本期完整收录「标准」「粉红恋爱向」两个示范，其他 4 个占位。
4. **房规系统**（[house-rules.md](campaigns/风骸岛之龙-demo/house-rules.md)）—— 7 段模板（战斗 / 治疗 / 休息 / 法术与施法 / 角色资源 / 桌面文化 / 其他），玩家自由定义；AI 涉及规则判定前**先查房规**再走 RAW。
5. **跑团循环（G2）**：场景描述 → 等玩家声明 → 投骰判定 → 结果叙事推进。
6. **战斗（G3）**：每回合 Edit `combat/active.md` 文件持久化先攻表 / HP / 状态 / 死豁 / 回合日志，跨多轮战斗状态不丢；战斗结束归档到 `combat/history/`。
7. **桌末同步（G6）**：按 7 步同步清单更新 sessions / players / progress / world-state / dm-notes / npcs / 战役 README。
8. **跨 session 恢复（G7）**：新对话说「继续上次跑团」，AI 按 11 步固定顺序读 `campaigns/<战役>/` 全套文件续接，无需你重复任何状态。

**内置机制**：

- **🔒 秘密物理隔离**：DM 秘密文件（伏笔、NPC 真实身份、揭示 DC）放在 `dm-only/` 子目录，AI 默认不读，揭示给玩家后同步更新公开档案
- **救场机制**：全队 down 时按模组兜底（如风骸岛 = 茹娜拉营救），救场配额在 `dm-only/dm-notes.md` 自动追踪
- **难度自适应**：按当前人数 + DM 风格 + 模组的「二级/三级冒险者」加成自动调整

### 5. 模组定制改写

SKILL.md **工作流 H** 让你按需求改写模组。AI 跑团是单人 / 双人居多，原版多为 4-5 人本，所以**改写**是刚需。同时玩家对风味（基调 / 性别 / 世界观 / 口音）需求各异。

**核心设计**：
- **全量副本**：原版只读，所有定制走副本 `docs/modules/<原模组>__<标签>/`
- **维度灵活**：不预设固定维度枚举，用户用自然语言描述（"单人 + 克苏鲁 + 主角性转 + 加同伴 NPC"、"双人治愈向 + 换成原创世界观" 等），Claude 解析成结构化改写计划，确认后执行
- **分层改写护栏**（最重要）：
  - 🔒 **数据原子不动**：附录 B 数据块、法宝数值、地图编号
  - 🟡 **数值层**（人数 / 难度信号触发）：动遭遇 + 协力 NPC，按缩放表自动算
  - 🟢 **风味层**（基调 / 性别 / 世界观信号触发）：动 README + NPC 描写 + 章节"读给玩家"叙事段
  - ⚪ **剧情骨架**默认不动（除非用户明确改 BBEG / 主线）
- **预览校验**：改完先给你看前 2 个改动较大的文件，确认基调对了再批量推完
- **改写清单**：副本 README 自动追加"基底 / 日期 / 改了哪些文件"，方便追溯和后续叠加

**示例**：
```
你：做一个单人克苏鲁向的风骸岛，让米拉狗头人作为协力 NPC 同行
Claude：
  1. 解析需求 → 给你看改写计划表（数值层：怪 HP×0.5；风味层：克苏鲁基调 / 米拉同行）
  2. 你确认 → 复制 docs/modules/风骸岛之龙/ 到 docs/modules/风骸岛之龙__单人克苏鲁向/
  3. 改写 NPC 速查 + 遭遇与战斗 + README + 章节叙事段
  4. 给你看 README + 第一章预览，确认基调
  5. 改完剩余文件，可直接开桌跑
```

## 安装

```bash
# 克隆到用户级 skills 目录
git clone https://github.com/ZGP0072600/dnd5r-skill.git ~/.claude/skills/dnd5r
```


## 用法示例

详细工作流见 [SKILL.md](SKILL.md)，简要：

| 你说 | Claude 做的 |
|---|---|
| 帮我用 X 车一张 N 级卡 | 按 SKILL.md 第 B 节流程：种族 → 职业/子职 → 背景 → 属性 → 专长 → 装备 → 法术 → HP/AC 结算 → 出 HTML 卡 |
| 改卡 / 升级 | Read 旧 HTML 提取嵌入 JSON → 改 → 重生成 |
| X 法术怎么样 | A 工作流：grep 法术速查 → 读详述 → 给环阶/学派/施法时间/距离/成分/持续/效果/升环/来源 |
| X 怪物 CR 多少 | D 工作流：grep 万兽大全 → 读详细页 |
| 某规则怎么裁定 | C 工作流：grep `进行游戏` / `术语汇编` |
| 战士 / 牧师 / X 职业有哪些子职 | E 工作流：跨书扫 PHB24 + PHB14 + 塔莎 + 珊娜萨 + 剑湾 + 费资本 |
| 你来当 DM 带我跑 X 模组 | **G 工作流**：G1 七步初始化战役 → G2 叙事循环 → G3 文件持久化战斗 → G6 桌末同步 |
| 继续上次跑团 / 上次跑到哪了 | **G7 工作流**：按 11 步固定顺序读 `campaigns/<战役>/` 全套文件续接，无需重报状态 |
| 做单人 / 双人 / 克苏鲁版 / 治愈向 / 性转版 / ... 的 X 模组 | **H 工作流**：解析需求 → 改写计划确认 → 全量副本 → 分层改写 |

`examples/` 下放了几张已生成的示范卡（兼职吟3术2、单职 7 级战斗大师、7 级混沌施法术士）可以直接打开浏览器看。

## 已知限制

- **法术位池单字段**：兼职多种施法者时，DC/法术攻击只用一个 `castingAbility`（一般兼职都同主属，问题不大；多施法属性混合时需玩家选主一个）
- **兼职 HD 共享一个 hdCur**：玩家自己心里记每种骰型用了多少（短休消耗时模板会按骰型分组询问，但不强约束某骰型的剩余）
- **豁免熟练自动化**：兼职规则只继承 1 级出身职业的豁免；玩家在 `abilities[ab].saveProf` 自己填
- **不全书更新**：当上游有新内容时，需要手动更新 `docs/extracted/`
